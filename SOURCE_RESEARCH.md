# Авточек — исследование источников каталога б/у автомобилей из Китая

Дата исследования: 2026-08-19

## Цель

Найти площадки, из которых в будущем можно получать карточки реально выставленных на продажу автомобилей с пробегом: фотографии, цена, пробег, комплектация, продавец, местоположение, состояние и устойчивый идентификатор объявления.

Первый детальный разбор: Che168 / 二手车之家 и Dongchedi / 懂车帝.

---

## 1. Che168 / 二手车之家

### Что видно в публичной карточке

Проверенные карточки содержат:
- устойчивый numeric listing ID в URL;
- dealer/store ID;
- марку, модель, версию/комплектацию;
- цену;
- признак включения/исключения расходов на переоформление;
- пробег;
- дату первой регистрации;
- коробку передач и объём двигателя;
- регион/город регистрации;
- количество переходов права собственности;
- экологический стандарт;
- текст продавца о состоянии машины;
- название продавца;
- количество автомобилей продавца в продаже;
- количество ранее проданных автомобилей;
- адрес продавца;
- набор фотографий конкретной машины.

Пример структуры URL карточки:
`/dealer/{dealer_id}/{listing_id}.html`

На отдельных дилерских страницах присутствуют признаки `新上` (новое объявление), `0次过户`, `质保`, `厂商认证` и счётчик текущих автомобилей продавца.

### Важное для Авточек

У Che168 есть отдельный mobile/card-detail контур, где в проверенной карточке отображались блоки `碰撞记录` (collision record) и `查看维修报告` (посмотреть отчёт о ремонтах/обслуживании). В пользовательском центре также присутствуют разделы заказов по ремонтно-сервисной истории и страховым событиям.

Это делает Che168 особенно интересным кандидатом для будущего сценария:

`карточка автомобиля → запрос отчёта → получение исходного отчёта → Авточек`

Точный текущий сценарий покупки отчёта, требования к логину, доступность VIN и возможность автоматизированной интеграции нужно проверять отдельно в реальной авторизованной сессии.

### VIN

В публичном HTML проверенных карточек VIN / 车架号 не найден. Поэтому на текущем этапе нельзя проектировать связь `listing → report` в расчёте на открытый VIN.

Потенциальные варианты связи позже:
1. VIN появляется только после авторизации или покупки отчёта;
2. VIN предоставляется продавцом;
3. VIN передаётся во внутреннем/партнёрском API;
4. отчёт можно заказывать по внутреннему listing ID без раскрытия VIN пользователю.

Это один из главных вопросов следующего исследования.

### Актуальность наличия

Дилерские страницы содержат текущий счётчик `在售车源` и карточки с признаками новых поступлений. При этом сама площадка предупреждает пользователя подтвердить наличие автомобиля у продавца перед визитом.

Поэтому в Авточек поле наличия нельзя хранить как вечное `available=true`.

Предлагаемая модель:
- `source_status = listed`;
- `last_seen_at`;
- `last_checked_at`;
- `seller_inventory_count`;
- `availability_confidence`;
- при заказе отчёта обязательно повторно проверять существование исходной карточки.

### Юридический/интеграционный риск

Текущий пользовательский договор Che168 прямо ограничивает коммерческое использование контента без письменного разрешения и отдельно упоминает операции роботами/спайдерами. Поэтому production-каталог Авточек нельзя строить на предположении, что массовый scraping разрешён.

Предпочтительный путь:
1. партнёрская/письменная авторизация;
2. официальный API или data feed, если доступен партнёрам;
3. прямые фиды от дилеров, которые одновременно публикуются на Che168;
4. только после этого — production ingestion.

Публичные страницы можно использовать для исследования структуры продукта и прототипирования схемы данных.

## 2. Dongchedi / 懂车帝

### Что видно в публичной карточке

Проверенные карточки содержат:
- numeric listing ID в URL `/usedcar/{id}`;
- марку, модель, версию;
- цену;
- сравнение с ценой новой машины;
- иногда финансовые предложения;
- пробег;
- дату первой регистрации;
- место первой регистрации;
- текущее местоположение автомобиля;
- количество переходов права собственности;
- двигатель/объём;
- коробку передач;
- способ обслуживания;
- цвет кузова и салона;
- текстовое описание состояния;
- оснащение и ключевые опции;
- продавца;
- количество автомобилей продавца в продаже;
- адрес продавца;
- часы работы;
- фотографии.

### Сильная сторона Dongchedi

В сертифицированных карточках есть структурированный `车辆检测` — собственный inspection layer.

В проверенной карточке были отдельные категории:
- accident inspection;
- core driving components;
- exterior;
- interior;
- chassis;
- flood inspection;
- fire inspection.

Внутри отображаются конкретные проверяемые элементы кузова и силовой структуры: лонжероны, стойки, зоны кузова, элементы салона и т. д.

Для Авточек это ценный дополнительный слой ещё до покупки исторического VIN-отчёта:

`объявление → состояние по осмотру площадки → исторический отчёт → наша аналитика`

### Каталог и фильтрация

Публичный каталог Dongchedi поддерживает:
- все автомобили;
- отдельную 4S-зону;
- фильтр/признак inspection report;
- сортировку по новым объявлениям;
- цене;
- возрасту;
- пробегу;
- марке/модели и другим параметрам.

Это делает площадку сильным кандидатом именно как источник витрины.

### VIN

В публичном HTML проверенной карточки VIN / 车架号 также не найден.

### Исторический отчёт

В публичной карточке есть inspection report и value-analysis элементы. В ходе этого исследования не подтверждён отдельный публичный сценарий покупки полной страховой + сервисной истории прямо из карточки, аналогичный тому, что просматривается в Che168.

Поэтому Dongchedi сейчас оценивается выше как источник каталога и inspection data, а Che168 — как потенциально более удобная точка для будущей связки `listing → history report`.

### Интеграция

У Dongchedi существует Enterprise Open Platform для коммерческих пользователей. Публичные документы подтверждают наличие enterprise-контура, аккаунтов организаций и API как класса интеграции, но в открытых материалах этого исследования не найден конкретный public API для выгрузки used-car inventory.

Production-вариант следует исследовать через enterprise/partner channel. Автоматизированный доступ к самой enterprise-платформе роботами прямо запрещён её текущим пользовательским соглашением.

## 3. Сравнение для Авточек

| Возможность | Che168 | Dongchedi |
|---|---|---|
| Публичные карточки автомобилей | Да | Да |
| Стабильный listing ID | Да | Да |
| Фотографии конкретной машины | Да | Да |
| Цена / пробег / регистрация | Да | Да |
| Данные продавца | Да | Да |
| Счётчик текущих машин продавца | Да | Да |
| Структурированный inspection | Частично/зависит от карточки | Сильный слой в сертифицированных карточках |
| VIN в публичной карточке | Не найден | Не найден |
| Намёк на сервисный/исторический report flow | Сильный | Пока не подтверждён |
| Дилерские inventory pages | Сильные | Есть seller inventory context |
| Production scraping без договора | Не закладывать | Не закладывать |
| Приоритет для каталога MVP | 1 | 2 |

## 5. Текущий приоритет

### Кандидат №1 — Che168

Причины:
- очень свежие дилерские inventory pages;
- большое количество конкретных dealer listings;
- стабильные listing IDs;
- публичные фото и основные характеристики;
- обнаружен отдельный контур collision/maintenance report;
- ближе к желаемой конечной цепочке Авточек.

### Кандидат №2 — Dongchedi

Причины:
- сильный каталог;
- хорошие фильтры;
- богатая карточка;
- структурированная проверка состояния;
- полезен как независимый дополнительный источник и для cross-check.

## 6. Следующее исследование

Перед написанием Catalog Collector нужно получить ответы на 5 вопросов:

1. Можно ли через партнёрский/enterprise доступ получать Che168 inventory официально?
2. Можно ли получить аналогичный feed от Dongchedi?
3. Когда и где Che168 раскрывает VIN для конкретной карточки?
4. Можно ли из конкретного Che168 listing ID перейти к платному history report без ручного ввода VIN?
5. Какие права партнёр получает на повторное отображение фотографий автомобиля на собственном сайте?

До ответа на эти вопросы scraping-код для production не писать.
