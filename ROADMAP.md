# Авточек — дальнейшая схема развития

## Целевая модель продукта

Авточек должен развиваться в сторону полноценной витрины автомобилей из Китая с возможностью заказать историю конкретной машины прямо из карточки.

### Пользовательский сценарий

1. Клиент открывает Авточек.
2. На сайте он видит каталог автомобилей: фото, основные характеристики, цена, VIN/идентификатор, продавец и другие доступные данные.
3. Клиент открывает карточку понравившегося автомобиля.
4. В карточке есть кнопка `Запросить отчёт`.
5. Клиент оплачивает отчёт на Авточек.
6. После подтверждения оплаты backend создаёт заказ на отчёт по конкретному автомобилю.
7. Сервис через авторизованный аккаунт на китайской площадке открывает карточку выбранного автомобиля.
8. Сервис запускает покупку/формирование отчёта на китайской площадке только для уже оплаченного клиентом заказа.
9. После получения исходного отчёта Авточек забирает его содержимое.
10. Система переводит данные на русский язык, парсит структуру, нормализует события и собирает единый отчёт Авточек.
11. Готовый отчёт становится доступен клиенту в его заказе.

## Схема системы

`Китайская площадка с автомобилями`
→ каталог/карточки/фото/характеристики
→ импорт и обновление каталога Авточек
→ карточка автомобиля на Авточек
→ клиент нажимает `Запросить отчёт`
→ оплата на Авточек
→ создание заказа
→ авторизованный сценарий получения отчёта на китайской площадке
→ исходный отчёт
→ парсинг
→ перевод
→ нормализация
→ анализ и пояснения
→ единый отчёт Авточек
→ выдача клиенту

## Архитектурные блоки

### 1. Catalog Collector

Задача: получать с китайской площадки каталог автомобилей, доступные фотографии и характеристики.

Сохраняемые сущности:
- внутренний `vehicle_id`;
- идентификатор автомобиля на исходной площадке;
- URL/идентификатор карточки;
- VIN, если он доступен;
- марка, модель, год, комплектация;
- пробег;
- цена;
- продавец/площадка;
- фотографии;
- дата последнего обновления;
- статус доступности автомобиля.

### 2. Авточек Marketplace

Публичный интерфейс:
- каталог автомобилей;
- фильтры;
- карточки с фотографиями;
- страница конкретного автомобиля;
- кнопка `Запросить отчёт`;
- статус автомобиля и актуальность данных.

### 3. Order Service

Отвечает за заказ отчёта:

`vehicle_id + customer_id → payment → report_order`

Статусы заказа:
- `awaiting_payment`;
- `paid`;
- `queued`;
- `purchasing_source_report`;
- `source_report_received`;
- `processing`;
- `ready`;
- `failed`;
- `refund_required`.

Главное правило: платная покупка исходного отчёта запускается только после подтверждённой оплаты клиента.

### 4. China Source Worker

Внутренний сервис, который работает с авторизованной сессией/аккаунтом китайской площадки.

Он получает конкретный `report_order`, находит исходную карточку автомобиля и запускает доступный официальный сценарий получения отчёта.

Должны сохраняться:
- площадка;
- идентификатор исходной карточки;
- время запроса;
- стоимость исходного отчёта;
- статус покупки;
- идентификатор полученного отчёта;
- исходный файл/данные;
- технический лог выполнения.

### 5. Report Pipeline

`Raw report → Parser → Translator → Normalizer → Analyzer → Avtocheck report`

Задачи:
- распознать структуру исходного отчёта;
- перевести китайские термины;
- привести события к единой модели;
- выделить пробег, обслуживание, ремонты, страховые события и риски;
- сохранить происхождение каждой важной записи;
- сформировать понятный интерфейс на русском языке.

### 6. Delivery

Клиент получает:
- статус формирования;
- готовый отчёт;
- дату формирования;
- идентификатор проверенного автомобиля;
- историю заказа;
- возможность повторно открыть купленный отчёт.

## Ключевой принцип продукта

Клиент взаимодействует только с Авточек. Все поставщики данных, авторизация на китайских площадках, покупка исходных отчётов, перевод, парсинг и нормализация работают внутри backend.

## Порядок реализации

### Этап A — текущий MVP
- лендинг;
- VIN-проверка интерфейса;
- визуальная модель отчёта;
- архитектура единого отчёта.

### Этап B — каталог
- определить первую китайскую площадку;
- изучить доступный способ получения каталога;
- импортировать карточки и фотографии;
- сделать базу автомобилей;
- реализовать каталог и страницу автомобиля на Авточек.

### Этап C — заказ отчёта
- создать сущность заказа;
- подключить оплату;
- связать заказ с конкретным автомобилем;
- сделать состояния выполнения заказа.

### Этап D — автоматизация получения отчёта
- авторизованная сессия на китайской площадке;
- открытие нужной карточки по исходному идентификатору;
- запуск покупки отчёта после события `payment_confirmed`;
- получение и сохранение исходного отчёта;
- обработка ошибок, повторные попытки, контроль двойной покупки.

### Этап E — автоматический Авточек-отчёт
- парсер;
- перевод;
- нормализованная модель событий;
- правила анализа;
- генерация пользовательского отчёта;
- выдача в личном кабинете.

### Этап F — масштабирование
- несколько китайских площадок;
- несколько поставщиков отчётов;
- дедупликация одинаковых автомобилей;
- обновление цен и статусов;
- другие страны и рынки.

## Технические риски, которые нужно проверить до автоматизации

- условия использования и допустимый способ автоматизированного доступа к выбранной китайской площадке;
- наличие API, партнёрского интерфейса или разрешённого сценария авторизации;
- устойчивость аккаунта, сессий, CAPTCHA/2FA и платёжного процесса;
- права на отображение и хранение фотографий и карточек автомобилей;
- возможность привязать исходный автомобиль к VIN и заказанному отчёту без ошибок;
- защита от повторной покупки одного отчёта;
- возврат клиенту при невозможности получить исходный отчёт.

До выбора конкретной площадки этот документ фиксирует продуктовую и техническую схему, а способ интеграции остаётся открытым для исследования.
