# Авточек — модель карточки автомобиля

## Зачем этот документ

Карточка автомобиля — центральная сущность будущего каталога Авточек. Пользователь должен выбрать автомобиль, изучить предложение и заказать отчёт, оставаясь внутри интерфейса Авточек.

Для первого эталона разобрана публичная карточка Audi A6L 2022 45 TFSI. Источник используется только как исследовательский референс структуры данных. В публичном интерфейсе Авточек название исходной площадки, её логотип, URL и технические идентификаторы не показываются.

## Что подтверждено в референсной карточке

- модель: Audi A6L;
- год/версия: 2022, 45 TFSI;
- первая регистрация: март 2022;
- город регистрации и нахождения: Линьи;
- количество переоформлений: 1;

## Визуальная иерархия карточки Авточек

### Первый экран

1. Галерея автомобиля.
2. Марка, модель, версия и год.
3. Цена.
4. Ключевые параметры: регистрация, город, двигатель, коробка.
5. Статус `Можно запросить отчёт`.
6. Главный CTA `Запросить отчёт`.

Пользователь должен понять предложение и перейти к проверке без перехода на внешний ресурс.

### Основные данные

Показываем:
- марку;
- модель;
- комплектацию;
- модельный год;
- дату первой регистрации;
- пробег, когда подтверждён;
- город;
- количество переоформлений;
- двигатель/тип силовой установки;
- коробку;
- привод, если доступен;
- кузов;
- цвета кузова и салона;
- VIN, только если его допустимо показывать и он подтверждён.

### Что известно до отчёта

Это отдельный слой от отчёта Авточек. Здесь можно показывать нормализованные факты из карточки продажи:
- заявленное обслуживание;
- известные заменённые элементы;
- комментарии о ЛКП;
- важные опции;
- предварительный inspection.

Любой такой блок должен быть явно подписан как предварительная информация из карточки продажи. Он не должен визуально сливаться с результатом проверки Авточек.

### Предварительное состояние

Структура:
- силовая структура / серьёзное ДТП;
- пожар;
- затопление;
- кузов;
- салон;
- ходовая.

Общий статус и конкретные замечания хранятся отдельно. Например, если общий итог говорит об отсутствии признаков затопления, но внутри проверки есть два замечания, пользователь должен видеть оба факта.

### Отчёт Авточек

CTA из карточки запускает цепочку:

`vehicle_id → availability check → цена отчёта → оплата → payment_confirmed → source job → raw report → parser → translator → normalizer → analyzer → Avtocheck report`

До подтверждения оплаты никакая платная операция у источника не запускается.

## Внутренняя backend-модель

Отдельно от публичного объекта:

```text

source_id
source_listing_id
source_url
source_account_id
source_payload_snapshot
source_last_seen_at

```

Frontend не получает эти поля.

## Принцип дедупликации на будущее

Одна физическая машина может встретиться в нескольких источниках. Поэтому карточка Авточек должна быть собственной сущностью:

`source listing A ┐`
`source listing B ├→ Avtocheck vehicle → report order`
`source listing C ┘`

Основные кандидаты для сопоставления: VIN, комбинация характеристик, фото-hash, продавец, цена, пробег и временная близость объявлений. VIN имеет наивысший приоритет, когда доступен.

## Текущий прототип

`vehicle.html` реализует эталонную страницу карточки на основе этой модели. Для галереи используются собственные демонстрационные изображения, чтобы прототип не зависел от внешней площадки. Название исходного источника в пользовательском интерфейсе отсутствует.
