# Catalog Collector MVP

Первый рабочий backend-контур каталога Авточек.

## Что умеет

- импортировать `.csv` и `.xlsx` через адаптер `SpreadsheetProvider`;
- использовать отдельную mapping-конфигурацию под каждого продавца/партнёра;
- нормализовать входные поля в единую модель Авточек;
- выдавать стабильный внутренний `vehicle_id`;
- хранить техническую связь с источником только внутри backend-хранилища;
- обновлять существующие объявления по `provider + source_listing_id`;
- при безопасном полном snapshot переводить исчезнувшие объявления в `inactive`;
- отдавать публичный каталог через `GET /api/vehicles`;
- отдавать одну машину через `GET /api/vehicles/:id`;
- отдавать значения для фильтров через `GET /api/vehicles/facets`;
- фильтровать на сервере по марке, городу, году, цене, пробегу, кузову, типу силовой установки и статусу;
- сортировать на сервере;
- использовать page-based пагинацию;
- передавать в карточку автомобиля data-driven блоки характеристик, фактов, состояния и оснащения;
- скрывать от публичного frontend `providerId`, `source_listing_id` и `source_url`;
- синхронизировать публичный экспортный каталог Autohome Global / Che168;
- получать карточки SeekAuto через публичный JSON proxy сайта и расширять выборку через рекомендации;
- читать одну публичную Che168 detail-card в pilot-режиме;
- обнаруживать карточки со страницы inventory конкретного Che168 dealer в pilot-режиме.

## Запуск

```bash
cd collector
npm install
npm test
npm run import -- --provider dealer-a --file ./data/incoming/example.csv --mapping ./config/providers/example.json --snapshot
npm start
```

По умолчанию API запускается на `http://localhost:8787`.

## Public API

### Каталог

```text
GET /api/vehicles
```

Поддерживаемые query-параметры:

- `q` — поиск по названию, марке, модели, комплектации, кузову, двигателю и городу;
- `brand`;
- `city`;
- `body`;
- `energy_type` — тип силовой установки;
- `engine` — совместимый legacy-параметр;
- `status=active|inactive|unknown|all`, по умолчанию `active`;
- `year`, `year_min`, `year_max`;
- `price_min`, `price_max`;
- `mileage_min`, `mileage_max`;
- `sort=updated-desc|year-desc|year-asc|price-asc|price-desc|mileage-asc|mileage-desc`;
- `page`, начиная с `1`;
- `page_size`, от `1` до `100`, по умолчанию `24`.

Ответ содержит:

```text
items
total
page
pageSize
totalPages
hasPrevious
hasNext
updatedAt
```

Старые `limit`, `offset` и `include_inactive=1` остаются совместимыми на переходный период.

### Значения фильтров

```text
GET /api/vehicles/facets
```

Возвращает марки, города, кузова, типы силовой установки, диапазоны года/цены/пробега и количество автомобилей по статусам.

### Одна машина

```text
GET /api/vehicles/:id
```

Карточка доступна и для архивной записи, если пользователь открыл ранее сохранённый `vehicle_id`.

## Data-driven карточка автомобиля

Помимо базовых полей Collector умеет принимать дополнительные публичные сведения:

- `description`;
- `features`;
- `listing_facts`;
- `condition_checks`;
- `extra_specs`.

Для CSV/XLSX простые списки разделяются `|`.

Пример:

```text
features:
Круиз-контроль|Камера 360|Подогрев сидений

listing_facts:
Владение::Один владелец|Сервис::Есть сервисные записи

condition_checks:
Кузов::Есть окрашенные элементы::warning|Пожар::Признаки не заявлены::ok

extra_specs:
Привод::Полный|Мощность::245 л.с.
```

Разделители настраиваются через `detailSeparator` и `detailPartSeparator` в mapping-файле. JSON-массивы в ячейках также поддерживаются.

## Подключение реального продавца

Для каждого источника создаётся mapping-файл. Исходные названия колонок могут быть любыми, включая китайские. Они сопоставляются с каноническими полями Авточек в `columns`.

Минимально необходимы:

- `source_listing_id`;
- `title` либо сочетание `brand + model`.

Для полноценной карточки рекомендуются цена, пробег, город, год, кузов, тип силовой установки, двигатель, коробка, характеристики, статус, `updated_at`, `photo_urls` и расширенные data-driven поля.

Фотографии в одной CSV-ячейке по умолчанию разделяются `|`. Разделитель меняется через `photoSeparator`.


Этот режим нужен для технической валидации структуры карточки до получения постоянного партнёрского feed/API.

## Che168 dealer inventory pilot

`Che168DealerInventoryProvider` начинает с:

```text
https://s.che168.com/dealer/carlist.html?dealerid={dealer_id}
```

Далее он:

1. ищет ссылки `/dealer/{dealer_id}/{listing_id}.html`;
2. обнаруживает ссылки пагинации на тот же dealer inventory;
3. дедуплицирует `listing_id`;
4. передаёт detail URL существующему `Che168PilotProvider`;
5. возвращает набор raw listings для общего Normalizer;
6. вычисляет `completeSnapshot`.

Ограниченный безопасный запуск для первых 20 машин:

```bash
npm run import:che168-dealer -- \
  --dealer 123615 \
  --limit 20 \
  --max-pages 10 \
  --concurrency 3
```

При `--limit` результат всегда считается частичным snapshot. Исчезнувшие машины при таком запуске не деактивируются.

Полный snapshot разрешается только при выполнении всех условий:

- Collector увидел объявленное количество автомобилей dealer;
- обход inventory страниц завершился без ошибок;
- лимит страниц не сработал;
- каждый обнаруженный detail URL успешно разобран;
- нормализация всех строк прошла успешно.

Если хотя бы одно условие не выполнено, импорт работает только как upsert найденных машин. Это защищает каталог от массовой ошибочной деактивации при сетевом сбое, изменении HTML или неполной пагинации.

HTML pilot не предусматривает обход CAPTCHA, авторизации или ограничений доступа.

## SeekAuto public JSON sync

SeekAuto подключён отдельным адаптером `SeekAutoCatalogProvider`. Для detail-карточек используется публичный JSON proxy, который вызывает frontend площадки:

```text
GET /api/proxy/cars/{car_code}/detail
GET /api/proxy/cars/{car_code}/recommends
```

Collector начинает с набора валидных `SC...` карточек разных марок и расширяет очередь через `recommends`. Для каждого найденного `car_code` затем отдельно запрашивается `detail`.

Запуск вручную:

```bash
npm run sync:seekauto -- \
  --limit 60 \
  --concurrency 2 \
  --recheck 20 \
  --missing-threshold 2
```

В публичную модель попадают название, марка/модель, год модели, дата регистрации, пробег, кузов, тип силовой установки, двигатель, коробка, фотографии, описание, сведения осмотра и площадка `SeekAuto`.

Цена сохраняется только тогда, когда источник возвращает точное числовое значение. Маскированные значения вида `¥2*****` не вычисляются и публикуются как `price: null`; валюта источника остаётся `CNY`.

Перед публикацией действует quality gate: карточка должна иметь осмысленное название, год или регистрацию, пробег, фотографии и достаточный набор технических полей. Старые ошибочные SeekAuto-карточки исключаются из публичного snapshot при следующей успешной синхронизации.

Повторная проверка старых карточек выполняется отдельно. Ответ `404/410` не деактивирует автомобиль мгновенно: статус меняется только после повторного подтверждения отсутствия.

GitHub Actions запускает SeekAuto sync каждые шесть часов. Техническое состояние провайдера хранится отдельно от публичного JSON-каталога.

## Snapshot-режим CSV/XLSX

`--snapshot` используется только для полной выгрузки конкретного провайдера. Если автомобиль присутствовал в предыдущем полном snapshot и исчез из следующего, Collector ставит ему `status=inactive`.

Для частичных выгрузок `--snapshot` не используется.

## Следующий production-шаг

JSON store остаётся MVP-хранилищем для проверки полного контура. Следующий шаг — PostgreSQL-репозиторий с тем же интерфейсом `Adapter → Normalizer → Store → Public API`.

Для официальных API/feed партнёров добавляется отдельный Provider Adapter. Normalizer и публичный API сохраняют текущую модель.
